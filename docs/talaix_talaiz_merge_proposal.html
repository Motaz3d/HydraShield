01

The idea

A single platform whose navigation contains one extra window — not a separate product.

What the customer experiences

They sign in to Talaix as they do today. In the left navigation, next to Dashboard, Reports, Maps and Intelligence, there is a new item: Agent Access. They open it like any other Talaix page.

  • Connect an AI agent (Claude, Cursor, ChatGPT…) to their Talaix data.
  • Choose exactly which Talaix tools each agent may call.
  • Watch every call in an audit log; approve sensitive ones.
  • Stop any agent instantly with a kill switch.

What it really is

The window is the talaiz engine — the Connector, the Gateway, the policy engine and the tamper-proof audit chain you already built — wearing the Talaix interface.

  • The engine is not rewritten; it is surfaced inside Talaix.
  • It gives Talaix a reason to keep customers inside the platform.
  • And it gives the talaiz engine the first-party data source it was missing: Talaix's own evidence tools.
02

What changes — and what stays exactly as it is

Your concern was losing the work. Here is the honest split.

CHANGES Presentation only

  • The name: "talaiz" is retired from the customer's view; it becomes the Talaix Agent Access window.
  • The entry point: the window lives inside the Talaix platform, not on its own site.
  • The visual design: the console is re-skinned with Talaix's colors, fonts and layout.
  • The billing: handled by Talaix's existing Stripe, not a second checkout.

STAYS The whole engine

  • The complete Go codebase: Connector + Gateway + protocol.
  • The 9 security properties: deny-by-default, outbound-only, SHA-256 audit chain, rate limits, redaction, human approval, kill switch, fail-closed, tenant isolation.
  • OIDC / SCIM / audit export / Postgres & bbolt — all of it.
  • The tests and e2e. Nothing is deleted, nothing is rebuilt from scratch.

04

Three ways to put the window in the platform

All three keep the Go engine intact. They differ only in how deep the integration goes.

Fastest — good for a first demo

A. Embed

iframe inside a Talaix page

A Talaix page hosts the existing talaiz console in a frame, under Talaix's header. Working window in days, minimal code.

  • Pro: almost no engineering.
  • Con: two sessions, less seamless.
Recommended

B. Reverse-proxy + SSO

talaix.com/app/agent-access

The talaiz gateway is served under a Talaix path behind the platform's sign-in. It looks and feels native — same domain, same session.

  • Pro: seamless, one sign-in, brand-clean.
  • Con: needs the SSO glue (below).
Deepest — later

C. Native rebuild

Talaix pages calling the talaiz API

Re-implement the console screens natively in the Talaix app, calling talaiz's REST API. Maximum polish, maximum work.

  • Pro: perfectly native UI.
  • Con: duplicates UI work.
05

The glue: one sign-in

This is the only real integration work — everything else is presentation.

How the window knows who you are

The customer signs in to Talaix once. When they open the Agent Access window, Talaix passes an identity to the talaiz gateway — either via OIDC (talaiz already supports it) or a short-lived signed token minted by the Talaix session.

  • Same account, same organisation, same billing.
  • No second login screen, no second password.

Where the customer's data lives

The Go gateway keeps its own store for connectors, policies and the audit chain — that stays. Talaix remains the source of truth for accounts, plans and invoices.

  • Two systems, one identity, one bill.
  • The audit chain is preserved exactly as designed.

07

Decisions needed from you

Four small decisions to start.

1

Window name

Agent Access, AI Access, Governance, or Agent Bridge? (Recommendation: Agent Access — plain and accurate.)

2

Build method

Start with A. Embed for a quick demo, then move to B. Reverse-proxy + SSO — or go straight to B?

3

Identity glue

Pass identity via OIDC (talaiz already supports it) or a signed token from the Talaix session?

4

The old talaiz site & billing

Retire talaiz's public site and Stripe entirely, or keep it hidden for direct customers while Talaix is the main door?
